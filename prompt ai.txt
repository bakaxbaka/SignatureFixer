### 3.5 COMPILER — src/compile.js
Pure function. Input: { tier, modules[], profile }. Output: the assembled block as a string.
Tiers: nano = kernel + phraseban. core = envelope + kernel + scope + livecheck + phraseban +
done + never + idem. full = core + loop + language.
Modules are additive flags that override the tier. Order of assembly is fixed and must match
the order the modules are listed in the tier table.
Profiles change exactly one word: the noun used for the target (agent | assistant | worker) and
the loop unit (iteration | turn). Nothing else.
The compiler must be a pure function: same input, same byte output. No dates, no randomness.

### 3.6 SCANNER — src/scan.js
Input: arbitrary text. Output: array of { hit, count, severity, why, fix }, sorted by severity
then count descending. Severities: high, medium, low. Include at least 18 rules. The rules must
cover, at minimum: "ignore previous instructions", "jailbreak", "you must", "override",
"pretend", "act as if", "you are now", "escalate privileges", "restricted", "safe", "ethical",
"for educational purposes", "at your own risk", "not financial advice", "it's important to note",
"keep in mind", "generally speaking", "results may vary", "consult a professional",
"use with caution", "feel free to", "let me know if", "would you like me to", "great question",
"I cannot", "I'm unable", "as an AI", unscoped "always" and "never".
Each rule carries a one-line reason and a one-line replacement.
Case-insensitive. Report every occurrence, not just the first.

### 3.7 UI — index.html
Single file. No build step, no frameworks, no CDN. Sections in this order:
1 tier selector, 2 profile selector, 3 module toggles, 4 generated block in a <pre> with a copy
button and live line/char/token counts, 5 scanner textarea with a "load sample" button and
results list, 6 the six method rules, 7 usage notes.
Copy must work without the clipboard API: fall back to a hidden textarea and execCommand.
Persist state in localStorage under the namespace thinkcore_. Handle missing storage gracefully.
The sample text for the scanner must produce at least 6 high-severity findings.

Document the six wording rules that keep the block from triggering: no identity claim,
no "ignore/override/jailbreak", explicitly additive, scope fence, idempotency clause, under 80
lines. One paragraph each, with the failure it prevents.

Applying a change and deploying it are separate operations. A passing test never triggers a
deploy. Before an overwrite, record the target's hash. After, verify the hash changed and only

crash fails the worker, never the parent.
